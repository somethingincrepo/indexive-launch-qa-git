<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What the three synthetic website review worksheets record</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Each worksheet covers one stage of a publishing check. Baseline Capture records the expected copy and URL. Public Readback records the observed response and content. Rollback Decision records a reason, a prior revision and a post-restore check. Our fictional QA pages cover each worksheet: <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-baseline-capture">Publishing Review Baseline Capture: Copy and Canonical URL</a>, <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-public-readback">Publishing Review Public Readback: Published Copy and Canonical URL</a> and <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-rollback-decision">Publishing Review Rollback Decision: Prior Copy and Canonical URL</a>.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Baseline fields can include the page title, which Google recommends be distinct, descriptive and concise, per <a href="https://developers.google.com/search/docs/appearance/title-link">Google's title link documentation</a>. A consistency check can also confirm that structured data matches visible content, since <a href="https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data">Google's structured data introduction</a> says markup should represent the visible page.</p>

<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Why a 200 status or a CMS timestamp is not enough</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}><a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/200">MDN's documentation on HTTP 200</a> says the status indicates request success, but a success status does not compare delivered copy with an approved draft. That comparison is the Public Readback job.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>A CMS record is a separate observation again. In Sanity, drafts and published documents are separate documents, with drafts carrying a drafts. ID prefix, and the published perspective excludes unpublished changes, per <a href="https://www.sanity.io/docs/content-lake/drafts-and-versions">Sanity's drafts and versions documentation</a>. Direct writes can also change a published document, so current text or updatedAt alone does not prove publication never occurred, according to <a href="https://www.sanity.io/docs/content-lake/drafts-and-versions">the same Sanity documentation</a>. If you don't know how the frontend is configured, don't assume it. The fictional <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-published-document">Sanity Published Document and Public QA Renderer</a> page keeps document state and public render apart.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What a rollback worksheet requires and how to record unknowns</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Restoring the old version is not the whole job. The worksheet also records why you rolled back, which prior revision you restored and what check you ran afterward. In this fictional specification, the Rollback Decision worksheet records a reason, a prior revision and a post-restore check, and nothing in the supplied material says more than that about how those fields work. After the restore, check the public page again, because a restore in the CMS and what the public page shows are separate observations.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Casey, a fictional editor persona, records each item as pass, fail or unknown and refers unresolved issues to a responsible reviewer. An unknown never counts as a pass. Some checks stay preliminary: <a href="https://www.w3.org/WAI/test-evaluate/preliminary/">W3C Easy Checks</a> are not proof of full accessibility conformance, and a noindex rule can't be seen if <a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing">robots.txt blocks crawling</a>. <a href="https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls">Google treats rel=canonical and redirects as strong signals</a> and sitemap inclusion as weaker, and canonical preferences should be consistent.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>In one controlled run, 17 deterministic synthetic fixtures went through rollback with file absence and public 404. These were software tests, not 17 customers or 17 AI-written articles. They do not establish production-worker results or general failure rates.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>How to choose the right worksheet and review scope</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Use Baseline Capture to record expected copy and URL, Public Readback to record observed response and content, and Rollback Decision to record a reason, prior revision and post-restore check. Choose the concept by the record you need, rather than treating any worksheet as a complete publishing system.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Keep expectations and observations separate</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>For a practice review, preserve the expected copy before comparing it with the public result. Put the public observation next to that expectation instead of replacing the expectation with whatever is live. This is a suggested way to use the two fictional concepts, not a promise about a worksheet feature or an automatic comparison tool. The definitions establish what each record contains, not a downloadable product or a software integration.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Choose the rollback record when a reversal is being considered</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>A rollback decision needs a reason, the prior revision and a post-restore check. Keep those details distinct from the original publication baseline. If the intended result is a restored prior page, compare against that prior revision. If a new test page is meant to be removed, record that different expectation. Do not infer that the 17-fixture removal result proves every kind of restoration.</p>

<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Frequently asked questions</h2>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What is a website review worksheet and what fields should it have?</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>It is a structured record of a publishing check. In these fictional specifications, fields cover expected copy and URL, observed response and content, and a rollback reason, prior revision and post-restore check.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What should be captured as a baseline before publishing?</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Capture the expected copy and the expected URL. Titles and structured data can be added so they can be compared later with what the public page shows.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>How do you verify published copy matches an approved draft?</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Read back the public page and compare its content with the baseline. Don't rely on the status code or a CMS timestamp, because neither compares delivered copy with the approved draft.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Does an HTTP 200 mean the content is correct?</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>No. It indicates request success only. The delivered copy still needs comparing against the approved draft.</p>

<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Inputs, roles and the pass, fail or unknown workflow</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The fictional editor persona Casey shows the sequence. Casey starts with a draft baseline, picks an expected public URL, runs a checklist, records pass, fail or unknown, and refers unresolved issues to a responsible reviewer. Casey is a persona who appears in this scenario only.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Unknown is a legitimate result. An unknown result means the check couldn't settle the question, so it goes to the reviewer role instead of being forced into pass or fail.</p>

Baseline Capture records the expected copy and URL, Public Readback records the observed response and content, and Rollback Decision records a reason, a prior revision and a post-restore check. All three are scenario specifications that exist only for this demonstration. <h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Why a successful response does not confirm the right copy is live</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>According to <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/200">MDN's documentation of HTTP 200</a>, that status indicates request success, and a status alone does not compare delivered copy with an approved draft. Public Readback therefore compares observed content with the baseline.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Draft state adds a second wrinkle. <a href="https://www.sanity.io/docs/content-lake/drafts-and-versions">Sanity's drafts and versions documentation</a> says drafts carry a drafts. ID prefix, the published perspective excludes unpublished changes, and later draft edits don't alter the published document until publication. Direct writes can change the published document, so current text or updatedAt alone doesn't prove publication never occurred. We don't assume any frontend configuration. The <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-published-document">Sanity Published Document and Public QA Renderer</a> page covers the same distinction.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What a passing preliminary check does not prove</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The <a href="https://www.w3.org/WAI/test-evaluate/preliminary/">W3C Easy Checks</a> cover titles, alternative text, headings, contrast and keyboard access, and passing them is not proof of full accessibility conformance. Basic explicitly excludes accessibility certification and ranking guarantees; Extended explicitly excludes WCAG conformance certification. Team adds no technical guarantees.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Other checks have limits too. <a href="https://developers.google.com/search/docs/appearance/title-link">Google's title link documentation</a> recommends distinct, descriptive, concise titles, and <a href="https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data">Google's structured data introduction</a> says markup should represent the visible page content. Per <a href="https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls">Google's duplicate URL guidance</a>, canonical tags and redirects are strong signals while sitemaps are weaker. <a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing">Google's noindex documentation</a> explains that a noindex rule can't be seen if robots.txt blocks crawling.</p>

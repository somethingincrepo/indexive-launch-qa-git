<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What the scenario does show is how a remote, worksheet-based review of a published page could work: what the reviewer records, what each check can and cannot prove, and what each fictional tier leaves out.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>What a remote review for Region A covers</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Region A and Region B are invented area labels with no real markets behind them. In the scenario, both are handled the same way: remote-only, browser-visible review with notes owned by the reviewer. No opening hours, local testimonials, credentials or real geographic coverage exist, and none should be read into this page.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The workflow runs in four moves. First, the reviewer records the intended baseline and any prior baselines, compares what the public page actually shows, records each check as pass, fail or unknown, and refers unknowns to the scenario's reviewer role.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Worksheets and the workflow behind them</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Three worksheet concepts carry the record. Baseline Capture notes the expected copy and URL. Public Readback notes the observed response and content. Rollback Decision notes a reason, the prior revision and a post-restore check. All three exist only as scenario specifications, and none is a downloadable product.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>They map onto the stated workflow of the public QA guide: baseline, change, publish, public verification. You can see the fictional specifications on <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-baseline-capture">Publishing Review Baseline Capture: Copy and Canonical URL</a>, <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-public-readback">Publishing Review Public Readback: Published Copy and Canonical URL</a> and <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-rollback-decision">Publishing Review Rollback Decision: Prior Copy and Canonical URL</a>.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Why an HTTP 200 does not confirm the published copy</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>HTTP 200 means the request succeeded. According to <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/200">MDN's documentation on the 200 status</a>, a response status alone does not compare the delivered copy with an approved draft, so the copy has to be checked separately.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>So the readback records the response and then the content, and compares both with the baseline. Several checks sit on top of that:</p>
<ul style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>
<li>Titles: <a href="https://developers.google.com/search/docs/appearance/title-link">Google's title link documentation</a> recommends distinct, descriptive, concise titles that accurately describe the page.</li>
<li>Structured data: <a href="https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data">Google's structured data introduction</a> says to choose markup that represents the visible page content, so JSON-LD is checked against what readers see.</li>
<li>Canonical signals: <a href="https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls">Google's guidance on duplicate URLs</a> treats rel=canonical and redirects as strong signals and sitemap inclusion as weaker, and says canonical preferences should be consistent.</li>
<li>Indexability: per <a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing">Google's documentation on blocking indexing</a>, a noindex rule can prevent indexing only when the crawler can access the page. A robots.txt block stops Google from seeing that rule.</li>
</ul>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Draft state and updatedAt do not prove publication</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>In Sanity, drafts carry a drafts. ID prefix and published documents do not. <a href="https://www.sanity.io/docs/content-lake/drafts-and-versions">Sanity's drafts and versions documentation</a> explains that the published perspective excludes unpublished changes, and later draft edits leave the published document alone until publication.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>That does not make a timestamp a verdict. Direct writes can also change a published document, so current text or updatedAt alone does not prove publication never occurred. We also assume nothing about how any particular frontend queries content, which is why public observation stays a separate check. The fictional reference page <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-published-document">Sanity Published Document and Public QA Renderer</a> separates published-perspective state from the renderer observation.</p>

<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Unknown results, rollback and self-managed review</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Casey, a fictional editor persona, starts from a draft baseline, picks the expected public URL, runs the checklist and records pass, fail or unknown. Anything unresolved goes to a responsible reviewer, and the notes stay with the reviewer. Unknown is a legitimate result to record rather than guess at.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>If a change has to be reversed, the Rollback Decision record holds the reason, the prior revision and a post-restore check. A labelled run of 17 deterministic synthetic fixtures included rollback with the file absent and a public 404. Those were software tests only, with no failure rates implied.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The fourth option is a self-managed review with a browser and an editor-owned checklist. No price is assigned, but the editor supplies the time, the expertise and an observation record.</p>

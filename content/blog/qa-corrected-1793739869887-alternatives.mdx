<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Demo Review Basic</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Basic costs an illustrative USD49 per exercise and covers one page. It includes an approved-copy checklist, a title and metadata comparison, a public URL check and a written exception list. Basic excludes code changes, accessibility certification, SEO ranking guarantees and recurring monitoring.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>That makes it a good fit when one page's copy and URL are the only worry, for example when you want to confirm the page that went live is the page you approved. It is a poor fit for any page with structured data or canonical questions, because Basic has no JSON-LD or canonical checks. If your page has either, you will leave real risks unexamined.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The title comparison deserves a caveat. Google recommends page titles that are distinct, descriptive, concise and accurate about the page (<a href="https://developers.google.com/search/docs/appearance/title-link">Google Search Central, title links</a>). A title can match the approved copy exactly and still fall short of that bar, so matching the draft is necessary but not the same as being a good title. Basic tells you whether the title matches; it does not rewrite it.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Basic also stops at the single exercise. With no recurring monitoring, a page that passes today is not watched afterwards. If a later edit changes the page, you would need to run another exercise. Our fictional catalogue lays out the three tiers side by side in the <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-demo-catalogue">Fictional Demo Review Catalogue for Basic, Extended and Team</a>.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Why a 200 response is not a copy check</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>A successful response from the public URL tells you less than it seems to. MDN documents HTTP 200 as indicating request success, and a response status alone does not compare the delivered copy with an approved draft (<a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/200">MDN Web Docs, 200 OK</a>). A page can return 200 and still show the wrong text.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>This is why Basic pairs its public URL check with the approved-copy checklist and the title and metadata comparison. The copy comparison happens in those checks. The public QA guide is a disposable, explicitly fictional page, set to noindex,nofollow, with a title, description, canonical and WebPage JSON-LD. It establishes no commercial outcomes.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Demo Review Extended</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Extended costs an illustrative USD149 per exercise and covers three pages. It keeps the Basic scope and adds JSON-LD and content consistency checks, canonical and indexability checks, preliminary keyboard, heading and image checks, and a rollback decision log. Extended does not certify WCAG conformance or fix production systems.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Take the structured data check first. Google describes structured data as explicit information about the meaning and content of a page, and advises choosing markup that represents the visible content (<a href="https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data">Google Search Central, structured data introduction</a>). Extended includes a JSON-LD and content consistency check, which is where a mismatch between markup and visible content would be examined.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The canonical check rests on a similar idea. Google treats rel=canonical and redirects as strong canonicalization signals, while sitemap inclusion is a weaker one, and your preferences should be consistent (<a href="https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls">Google Search Central, consolidating duplicate URLs</a>). Extended includes canonical and indexability checks, so consistency between your canonical signals falls within its scope.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The indexability check has a trap worth knowing. A noindex meta tag or response header can prevent indexing when the crawler can access it, but blocking crawling in robots.txt prevents Google from seeing that rule (<a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing">Google Search Central, blocking indexing</a>). If robots.txt stops Google from reading the noindex rule, Google cannot see that instruction.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The rollback decision log is part of Extended. The supplied definition does not spell out what the log contains. Separately, our fictional Rollback Decision worksheet concept records a reason, a prior revision and a post-restore check, and it is described in the <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-rollback-decision">Publishing Review Rollback Decision page on prior copy and canonical URL</a>. Treat the worksheet as a separate scenario specification, not as the log's contents.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Extended fits several related pages with structured data or duplicate-URL risk. It is a poor fit if you need a conformance statement, or if you expect it to repair anything. Extended does not fix production systems.</p>
<h3 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Do passing preliminary checks mean the page is accessible?</h3>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>No. The W3C's Easy Checks cover page titles, alternative text, headings, contrast and keyboard access, and passing them is not comprehensive accessibility conformance proof (<a href="https://www.w3.org/WAI/test-evaluate/preliminary/">W3C WAI, preliminary checks</a>). Extended runs preliminary keyboard, heading and image checks and explicitly does not certify WCAG conformance.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>If you need conformance evidence, for a procurement or legal reason, you need a different kind of review than any of the four options here.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Demo Review Team</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Team costs an illustrative USD299 per exercise and covers ten pages. It uses the Extended checklist, adds a shared sign-off sheet and provides two reviewer roles. The prices are authored test data.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Be clear about what you are buying. Team adds review coordination only, and the technical checks stay the same as Extended. The checks match Extended, and the difference is who reviews and who signs off. If someone tells you Team is more technically thorough, the definition does not support that.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Team fits larger page sets with more than one responsible person, where a single record of who checked what and who approved it saves argument later. It is a poor fit for one or three pages, because the coordination cost buys no extra verification there. For a single page, Basic is the better choice, and for three pages Extended covers the same checks.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Self-managed review</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>A self-managed review uses a browser and an editor-owned checklist. No software price is assigned, and it is not a named vendor. That does not make it free. The editor supplies the time, the expertise and a record of observations, so the cost is labor and skill.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Casey, a fictional persona and not a real customer, shows the workflow. The workflow runs from a draft baseline: Casey selects an expected public URL, runs the checklist and records each item as pass, fail or unknown. Anything unresolved goes to a responsible reviewer. The unknown category lets an editor record an unverified check as unverified instead of guessing.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Three worksheet concepts support this. Baseline Capture records the expected copy and URL, described in <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-baseline-capture">Publishing Review Baseline Capture for copy and canonical URL</a>. Public Readback records the observed response and content, described in <a href="https://scoring-spell-mailing-lenses.trycloudflare.com/qa-semantic-public-readback">Publishing Review Public Readback for published copy and canonical URL</a>. Rollback Decision records a reason, a prior revision and a post-restore check. All three are fictional scenario specifications, not downloadable products.</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Self-managed review fits an experienced editor with few pages. It is a poor fit without a second reviewer for unknown results, because an unknown result needs a responsible reviewer to resolve it.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Why a draft edit or updatedAt does not show the public page</h2>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Whichever option you pick, verify the public page and not the editor. Sanity drafts carry a drafts. ID prefix, published documents do not, and the published perspective excludes unpublished changes. Later draft edits do not alter the published document until publication (<a href="https://www.sanity.io/docs/content-lake/drafts-and-versions">Sanity documentation, drafts and versions</a>).</p>
<p style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>The drafts perspective applies drafts for preview, and direct writes to the published document can also change it. So current document text or an updatedAt value alone does not prove publication never occurred, and it does not prove what visitors see either. A public frontend that uses the published perspective excludes draft-only edits, but an unknown frontend query or delivery configuration must not be assumed. The only safe move is to read the public page back separately.</p>
<h2 style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>Verdicts by scenario</h2>
<ul style={{"maxWidth":"100%","overflowWrap":"anywhere","boxSizing":"border-box"}}>
<li>One page, with copy and URL as the only worry: choose Basic.</li>
<li>Up to three pages with structured data, canonical or indexability questions: choose Extended.</li>
<li>Ten pages needing two reviewer roles and a shared sign-off: choose Team.</li>
<li>An experienced editor with time and a second reviewer for unknowns: run a self-managed review.</li>
</ul>

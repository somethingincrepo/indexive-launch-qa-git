<p>A canonical URL is the representative address that Google Search selects for a group of duplicate pages. The process of choosing it is called canonicalization, a search deduplication step that never tells a browser to navigate elsewhere. Site owners can state a preferred URL, but that preference and Google's selection are separate things.</p>
<p>Google's own wording is set out in <a href="https://developers.google.com/search/docs/crawling-indexing/canonicalization">Google's canonicalization documentation</a>, which is the source for this definition.</p>
<h2>Canonical URL definition</h2>
<p>A canonical URL is the page chosen to represent a group of duplicates in Search. Canonicalization is a search deduplication process, and a browser never treats it as an instruction to navigate elsewhere.</p>
<h2>Examples of duplicate URLs</h2>
<p>These patterns are illustrative examples and are not drawn from any dataset. Each shows one page reachable at several addresses.</p>
<ul>
<li>Trailing slash: the same page opens at /pricing and at /pricing/.</li>
<li>Hostname: the same page opens under www and under the bare domain.</li>
<li>Tracking parameter: the same page opens at /pricing and at /pricing?ref=newsletter.</li>
</ul>
<p>In every case the content is identical, so one URL has to represent the group. That is the job canonicalization does.</p>
<h2>How preferred URL signals work</h2>
<p>You can point toward your preferred URL in several ways, and they do not carry equal weight. According to <a href="https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls">Google's guidance on consolidating duplicate URLs</a>, rel=canonical and redirects are strong signals, while including a URL in a sitemap is a weaker one.</p>
<p>Google says canonical preferences should be consistent. Even a clean declaration remains a preference, because your preference and the URL Google selects are distinct.</p>
<h2>Canonical URL versus redirect and noindex</h2>
<p>These three are easy to confuse because they all deal with unwanted URLs. They behave differently.</p>
<p>A 301 redirect means the resource has moved permanently. <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/301">MDN's 301 reference</a> explains that the Location header names the destination, and the browser then requests that URL. A canonical link alone implies no redirect and sends no visitor anywhere.</p>
<p>Noindex is about keeping a page out of the index. Per <a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing">Google's documentation on blocking indexing</a>, a noindex meta tag or header can prevent indexing when the crawler can access it. If robots.txt blocks crawling, Google never sees the rule. So a canonical consolidates duplicates, while noindex keeps a page out of the index, and a robots.txt block can hide the noindex from Google.</p>
<h3>Checking the canonical on the published page</h3>
<p>Sanity's documentation says drafts and published documents are separate, and later draft edits do not change the published document until publication. Document text or updatedAt alone does not prove publication never occurred, and you should not assume how a frontend delivers content. An HTTP 200 only shows the request succeeded; it does not compare delivered copy with the approved draft. Read the canonical on the public page itself.</p>

<h2>Related terms</h2>
<ul>
<li>Canonicalization: the search process that selects a representative URL for duplicate content.</li>
<li>Duplicate content: the same page reachable at more than one URL.</li>
<li>301 redirect: a permanent move that makes the browser request the destination.</li>
<li>Noindex: a meta tag or header that can prevent indexing when the crawler can read it.</li>
<li>robots.txt: a file that can block crawling, which stops Google from seeing a noindex rule.</li>
<li>Sitemap: a list of URLs whose inclusion is a weaker canonical signal.</li>
</ul>
<h2>Canonical URL questions</h2>
<h3>Will Google always use my canonical?</h3>
<p>No. A declared canonical is a preference, and the URL Google selects can differ. Google recommends keeping canonical preferences consistent.</p>
<h3>Does a canonical redirect visitors?</h3>
<p>No. Canonicalization is search deduplication and never sends a browser anywhere. Only a redirect such as a 301 makes the browser request another URL.</p>
<h3>Can I use noindex and a robots.txt block together?</h3>
<p>It defeats the purpose. Google can only act on noindex when it can access the page, and a robots.txt block prevents it from seeing the rule.</p>
<h3>Which signal is strongest?</h3>
<p>Google treats rel=canonical and redirects as strong signals. Sitemap inclusion is weaker, so keep all of them pointing at the same URL.</p>
